第4层 - 订单数据库 技术栈详解

Layer 4 - Order Database Tech Stack

  • Supabase/PostgreSQL: 订单主数据库，JSONB 扩展存储半结构化数据Order master DB with JSONB extension
  • item_versions: 版本追踪表，每次变更生成新版本记录Version tracking, new record per change
  • JSONB 可追溯: 每个字段嵌入来源证据，哪个文件提取了一目了然Each field embeds source evidence JSONB

组合效果：结构化存储 + 版本完整追溯，字段都可看到来源

Synergy: Structured storage + full version trace

第5层 - 规则与 Agent 层（核心）

Layer 5 - Rule & Agent (Core)

  • 业务规则引擎: 供应商匹配/字段校验/版本判断规则Supplier matching, field validation rules
  • AI Version Agent: 自动判断最新需求版本，语义理解而非只看时间戳Auto-determines latest version by context
  • Risk Scorer: 评估订单风险，低风险自动通过Scores order risk, auto-approve low risk

组合效果：规则兜底 + AI 智能判断 + 风险量化

Synergy: Rules + AI judgment + risk quantification

第6层 - 确认与审批层 技术栈详解

Layer 6 - Approval Layer Tech Stack

  • Human-in-the-loop: 高风险字段人工逐条确认，业务安全边界High-risk fields require manual confirmation
  • Approval Queue: 待确认队列，按风险等级排序，优先处理重要订单Queue sorted by risk level and urgency
  • 版本证据展示: 展示字段变更历史和来源证据，帮助人工快速判断Shows change history for quick judgment

组合效果：AI 辅助 + 人工兜底，安全与效率平衡

原生版本管理架构

item_versions + 时间戳索引 + JSONB 来源证据，从架构层面解决"哪个是最新版本"的核心问题，而非后期打补丁

item_versions + timestamp indexing + JSONB source evidence, solves "which version is latest" at architecture level, not as an afterthought

规则 + Agent 分层决策

Rule + Agent Layered Decisions

规则引擎兜底，AI Agent 智能判断，Risk Scorer 量化风险。不是纯规则（死板）也不是纯 Agent（不可控），而是分层混合

Rules as safety net, AI Agent for intelligent judgment, Risk Scorer quantifies risk. Not pure rules (rigid) or pure Agent (uncontrollable), but layered hybrid

3

Human-in-the-loop 安全网

Human-in-the-loop Safety Net

高风险字段强制人工确认，不过度承诺自动化。AI 负责整理，人负责决策，安全与效率平衡

High-risk fields require mandatory human confirmation, no over-promising automation. AI handles consolidation, human decides, balanced safety and efficiency
